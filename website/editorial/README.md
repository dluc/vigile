# The editorial pass over the web site

This file is not part of the public site. It records, for every public page, what the page is for and whether it
earns the attention it asks. A page without a row here fails the site's test (`website/site.test.mjs`), so a
new page cannot skip the pass. The rows are written by a person or an agent who read the page; nothing here is
made by the build.

## How to read a page

Read it as someone deciding whether to spend attention and money on Vigile, who has other tabs open. Ask, in
this order:

1. **Does it sell Vigile?** Is there a specific reason on this page to choose it rather than a list of issues,
   a file of notes and prompts, or another tracker?
2. **Is every claim true in the product as it is now, without inflation?** A claim that needs evidence links to
   the behaviour, the reference page, the picture or the diagram that shows it. A claim that cannot be shown
   comes out.
3. **Is it relevant to the reader's decision at that moment?** Detail that is true and belongs later goes to
   How it works or to the Documentation.
4. **Would what the page shows be worth paying for?** Say the value in concrete terms: less coordination lost
   between agents and people, wrong moves refused, what can start now, history and conflicts, the plan on your
   own machine. Say the limits as plainly. Never invent a price, and never say that it is paid.
5. **What would make it worth more?** That goes into the report of the pass, as suggestions for the product. It
   never goes onto the site: the site says what is built.
6. **How much attention does it ask before the value is understood, and would you give it?** The home page has
   to be understood in a minute and answer, in this order: what, for whom, why this, show me, let me try. Every
   page has to earn its next screen. Shorten, split, move or remove what does not.

## Rules of the site that the pass holds it to

- Today and direction are kept apart, by a label the reader sees. What can be used today is said as fact and
  links to where it is shown. A direction, which is where the design could go, stands only in a place marked
  "Direction": on the first page's one card and on the vision. It says that it is not built, and has no date, no
  price, no customer, no "will". A row that is some of each is marked "Mixed" and says which part is which.
  Everywhere else, what is not built is named as a limit ("it has none"), not as a plan. The test holds this
  (`site.test.mjs`, "what it says of the future").
- The limits of today stand next to trying it, and on the vision under "What it is today". They are not hidden
  by the vision, and they are not the centre of the site.
- No other product is named, and nothing is said of one that was not checked.
- A number on the site comes from what the program says of itself (`vigile describe`), from what a service did
  when the site was built, or from a measurement written down here.
- "Live", "as it happens": only together with the condition (auto-refresh is off until switched on).
- The words follow the product: what it refuses, it "refuses"; what it works out, it "works out".
- A command on a page works as typed. Every block of commands says which terminal it is typed in, and a new
  terminal starts with nothing: a page that opens one gives it what it needs. The test types them.
- A failure is never said to mean that nothing happened, unless the code makes it so. Of an exit code, an
  error code or a missing answer the page says what may have been changed, and what to look at before trying
  again. No page says "just try again".
- An instruction is safe to follow in the order it is given: looking comes before sending again.
- What the service does is said from a fact, not from memory. `website/lib/facts.mjs` reads from the
  description the program prints which operations take a version and which answer in pages, and
  `website/lib/contract.mjs` asks a real service, started through the program, what an answer carries and which
  end of a link records it; the pages are made from those answers, or the test holds their sentences to them. A
  sentence with "every", "all", "always", "never", "both" or "any" in it about the service is one of three
  things: made from such a fact, held to one by a test, or reworded to what was checked.

## How to make a pass

1. Build the site and read each page in a browser, phone and wide.
2. For each page, answer the six questions, and change the page where it fails one.
3. Check each claim against the product: run the command, read the operation's page (its example is run by the
   build), or read the code. Write down what was checked. For a claim about what a command or an error leaves
   behind, read the code that ends that way, not only the README.
4. Update the page's row below: the value in one sentence, what was checked, the attention it asks, the verdict
   and the date. Add a row for a new page; remove the row of a page that is gone.
5. Run `node --test website/site.test.mjs`.

The columns:

- **Attention**: the time to the point, where the reader knows what the page gives them, and the time for the
  whole page, at about 230 words a minute with tables and code scanned.
- **Verdict**: what the pass decided for the page. `keep`: as it is. `shorten`, `move`, `rewrite`: what was
  done to it in this pass, or, when followed by "open", what is still to do.

Is "it guides, and does not only store" a reason for a platform or a team that runs agents to choose Vigile?
Today it is a reason to try it: the loop is taught in three places from one source, and the tools refuse the
stale and the unsafe move. It is not yet a reason to standardise on it: that the guidance makes agents plan
better is asserted by the design and not measured, and the parts a platform would pay for are direction.

## Measurements behind the claims

- **"Try it in two minutes"** (home page). Timed on 2026-11-13 on a copy of the repository without its
  dependencies: `pnpm install` 1 s with the packages already in pnpm's cache, `pnpm build` 1 s, `config init`
  and `serve` under 1 s each. With an empty cache the install is the time to download the dependencies, which
  was not measured. Two minutes leaves room for that and for typing the commands.
- **"Sends nothing anywhere"** (home page, Security). Read on 2026-11-13: the service, the engine, the store and
  the page make no outgoing request; the only requests in the code are the command line's to its own service.
- **"Two agents cannot take the same task"**. The second `set_task_status` with the version first read is
  refused with `version_conflict`; with the new version, with `same_status` and the advice to pick other work.
  Both are on the page of `set_task_status`, whose examples are run by the build.
- **The home page before and after this pass**: 1,239 words and 12 screens on a wide window before; 740 words
  and 8 screens after. After the rewrite around the vision: 764 words; the first screen, which says what Vigile
  is, what can be used today and what is direction, has 151 words, 40 seconds at 230 words a minute. The vision
  has 996 words. The test holds all three (800, 153 and 1,000).
