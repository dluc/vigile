Planning and coordination for people and AI agents

People and agents, working from one plan.

When agents do real work beside people, the plan is what they all share. Vigile holds it as one graph of outcomes, dependencies, responsibility, state and history, changed only through checked operations: true enough to act on, and open for an agent to inspect and improve.

Use today

One service, on your machine

For coordinating several agents and people. MCP, HTTP, a command line, a board, a graph, a history, a decision register; quiet claims and automatic backups. Version {{=version}}: no TLS, no access by team.

Today · why not a list of issues, or a file of notes

Three things a list does not do for you.

what can start now

It works out what can start

Say what depends on what and set priorities on areas and tasks. Vigile follows the active path from outermost group to task, holds work back for unfinished dependencies or inactive containers, and answers "what can I do next?" each time it is asked.

How next and waiting are worked out

{{diagram next}}

refusals

It refuses a wrong move, and says what to do

Starting a task whose dependency is unfinished, closing a group over open work, a jump of status the rules do not allow: each is refused, and the refusal says why, and what would resolve it, for a person to read or an agent to follow.

The rules, and what a refusal carries

$ vigile set-task-status --id WEB-003 --version 1 \
    --status in_progress --as agent1

✗ Task WEB-003 cannot be started: it is waiting for a
  dependency to finish.
  · WEB-002  Cart page lists the items and the total  open
  → Finish or cancel the items it depends on.
  → Or call remove_link with type "depends on" if the
    dependency no longer applies.
  → Or call list_next_tasks to pick work that can start now.

versions

Two agents cannot take the same task

Changing a task names the version the change was based on. Of two agents that start the same task, one is refused. Assigned work quiet for 24 hours can be listed for attention, but is never silently taken away.

And it keeps the plan in sight

See the work without asking the agents.

The whole plan in one picture, grouped into areas, with its dependencies, its work in progress and its priorities, also shows how the work is cut: tasks that belong to no group, a group grown too wide, too many unrelated things started at once. An agent can read the same plan through the same lists.

  • Groups, as deep as the work

    A task that contains tasks is a group, and reports how far along it is. Groups

  • Contradictions are flagged

    Reopen a dependency after the work that needed it went on, and the task and its project say so. Problems

  • Decisions and history, kept with the work

    A decision has its reasons and a state, and is listed on the work it affects. Every item keeps its history. DecisionsHistory

  • A board, a graph and a history

    Zoom the board into a project or through nested groups, filter it, read who changed what across the plan, inspect an item and adjust task priority. Every view, selection, item and zoom has an address. The web page

A tool, an endpoint and a command, under the same rules.

Try it in two minutes

One process. One folder. Yours.

It needs Node.js {{=node.needed}} or later and pnpm. No database server and no account. It listens on 127.0.0.1, sends nothing anywhere, and takes a backup every 24 hours by default.

Install and first run, step by step

  1. Get it and build it.

    git clone {{=repo.url}}.git ~/code/vigile
cd ~/code/vigile
pnpm install
pnpm build

  2. Create an instance and start it.

    cd ~/code/vigile
bin/vigile config init --config ~/vigile/main/config.toml --name main
bin/vigile serve --config ~/vigile/main/config.toml

  3. Open the board, and point an agent at the plan. serve prints where everything is:

      MCP      http://127.0.0.1:8700/mcp
  Web      http://127.0.0.1:8700/
  API      http://127.0.0.1:8700/api

Today · said plainly

What it does not do.

  • No comments, attachments or due dates.
  • No access by team or by project: whoever is let in can change the whole plan.
  • No general editing in the browser: only a task's priority has −/+ controls.
  • No hosted service, and no import, export or links to other tools.
  • No TLS of its own, and it does not install itself as a service: you keep the process running.

Vigile is new: version {{=version}}, developed and tested on Linux, under the MIT licence. Where it could go, and why that is credible, is on the vision, marked as direction.
